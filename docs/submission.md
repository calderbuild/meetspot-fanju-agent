## 作品信息

**作品名称**：MeetSpot 饭局 Agent：去哪吃、点什么一次谈拢

**一句话形态**：一个网页智能体（手机打开即用）。几个朋友每人说一句要求，它先把不合适的餐厅划掉，到店拍一下菜单，再出一张大家都能吃、不超预算的点菜单。

**动机**：朋友聚餐时，最耗时间的往往不是吃，是在群里来回商量。有人吃素，有人不吃海鲜，有人预算紧，还有人过敏，每个人都得把这些再说一遍；到了店里，点菜又得重来一轮。我在许愿池看到《做个聚餐点菜避踩雷小助手》这条愿望，和我做 MeetSpot 时反复遇到的问题是同一件事，所以做了这个。

**作品链接**：https://render.qmuse.pub/p/muse/3163078624095246

## 作品说明

### 目标用户和问题

两到八个人约饭的朋友、同事、同学。痛点有两个：

1. 选店时，每个人的忌口和预算散落在群聊里，没人能一次记全，常常到了才发现有人没东西可吃。
2. 点菜时，一个人拿着菜单替大家点，很难同时照顾到吃素、过敏、预算这几件事，结账才发现超了。

### 核心功能和使用方法

1. **谁来吃**：每人填称呼、从哪出发、一句话要求（例如「我吃素，人均别超过 100」）。也可以直接点「用示例饭局试一下」，不用打字就能看完整流程。
2. **去哪吃**：模型把每个人的原话整理成可检查的限制条件，并把整理结果列出来给大家核对；系统在大家的中间位置搜附近的餐厅，按预算和品类逐家排除。每一家被划掉的店都写明是谁的哪条要求、命中了哪个词（例如「小李（不吃海鲜）招牌菜含『鱼』」）。留下的店标注「按品类初筛，未核实」，不假装已经确认过菜品。
3. **点什么**：到店后拍菜单，模型只读照片里真实出现的菜名和价格，读错的地方可以直接改；不在店里也可以点「用一张示例菜单试试」，用一张真实的餐厅菜单照片走完这一步。再按每个人的限制出点菜方案，代码逐条核对：菜名必须在菜单上、总价按菜单价格算、每个人至少有两道能吃的菜、人均不超预算。不合格就让模型改一次，还不合格就如实列出哪一条没满足。
4. 过敏只做提示，并固定显示「过敏原请向店员确认」。

**特色**：模型负责听懂人话和读菜单，规则判断全部由代码完成、可以逐条检查。每一次否决都有理由，点菜单上的每道菜都能在照片里找到。

### 与 MeetSpot 的关系

这是新作品，代码在新仓库里重新写。复用的是我自己在 MeetSpot 里验证过的思路：取多人的中间位置，以及记录每一次否决的原因。MeetSpot 已参加过别的赛事的通勤公平性功能，这个作品没有用，也不做距离或通勤时间的公平性评分。

### 使用的模型、工具和数据来源

- 模型：阿里云百炼 `qwen3.7-flash`（理解每个人的要求、识别菜单照片、生成点菜方案）
- 餐厅数据：高德地图 Web 服务（地理编码、周边餐饮搜索）
- 开发与部署：QMuse（React 前端 + QMuse 云函数），本地用 QMuse CLI 导入
- 代码：GitHub `calderbuild/meetspot-fanju-agent`（MIT）
- 示例菜单照片：广州莲香楼菜单实拍，Wikimedia Commons 用户 MeiOLA 2290 WMENSZ 拍摄，CC0。页面上标明是示例，不是所选餐厅的菜单
